# KV260 智能车新模型转弯差速不足：离线诊断与修复实验报告

日期：2026-10-27  
范围：只读源码/既有证据、离线推理、特征分析、一次预注册微调；未连接 KV260、相机、串口、电机或车辆，未修改生产目录、`bit`、`params.json` 或原模型。

## 1. 结论先行

### 1.1 最可能的根因

**最可能不是部署链路，而是“新模型训练数据的场景—标签联合分布与现场不匹配”。** 更具体地说：

1. 现场图像相对原训练集存在可测量的特征分布偏移。
2. 偏移不能单独解释塌陷；很多与训练集相近的现场大转弯帧仍然塌陷。
3. 这些现场帧的最近训练样本主要来自大转弯标签极少的录像包，且相似弯道上的原始 `joystick.csv` 标签差速经常只有约 0–20，而旧模型现场输出可达 40–60 以上。新模型的输出与这些较小的最近邻标签更一致。
4. 因而，“全局 MSE 必然把大转弯回归均值”不是主解释；更准确的是**特定视觉场景里缺少足够的大转弯示范，以及新旧模型对同一场景的控制响应先验不同**。
5. 旧模型实际训练数据、checkpoint 和标签来源缺失，所以不能进一步断言“旧模型标签定义不同”或“新标签在物理上错误”。旧模型只是本轮现场参照，不是真值。

### 1.2 赛前替换判断

**当前不能认定任何新候选可在 2026-10-28 比赛前安全替换。保底方案仍是旧模型 CPU。** 原新模型、B 候选和本轮 `field_distill_mix01` 都没有现场闭环验收；本轮候选还明确未过离线门禁。

本轮唯一微调候选在训练运行上几乎拟合教师，但跨运行留出明显改善不足，同时损害原开发集大转弯和事件指标。**它只能作为失败证据保留，不应复制到生产或替换旧模型。**

### 1.3 重要待确认

- 用户尚未确认旧模型在这两圈里是否全部正常过弯、是否无接管/出界；因此“旧模型能转过去”仍是参照假设，不计入已验证的整圈任务成功。
- 现场数据全部由旧模型轨迹产生。没有新模型闭环数据，无法离线证明新模型接管后会进入什么状态，也无法证明增大输出后一定安全过弯。

## 3. 证据链

### 3.1 部署与回放身份不是本轮异常来源

- 既有 635 组五路回放中，旧模型重放与现场记录最大差 `0.0001220703125`；本轮现场缓存又逐帧验证了 uint8 YUV→归一化 LUT 与生产预处理逐位一致。
- 本轮特征 PyTorch 路径对既有 FP32 的最大差：开发集 `0.0001373291`、现场 `0.0001678467`，门槛 `0.001`。
- 相机干预身份回放最大差：旧模型 `0.0001220703125`、新模型 `0.0001373291`。
- 本轮不重新把问题归因于量化；原新模型 FP32 与整数前端的现场总体表现相近。完整四路径也显示候选在两条路径上均失败，不能靠 FP32/整数路径差异解释或挽救任务效果。

证据：`results/field_cache01/field_identity_cache_manifest.json`、`results/features01/features_manifest.json`、`results/camera_interventions01/field_intervention_manifest.json`。

### 3.2 现场塌陷确实存在，且不是单一运行偶发

以旧模型 `|d|>40` 为固定参照掩码，198 组中：

- 旧模型平均 `|d|=59.207`；新 FP32 为 `22.413`。
- 新 FP32 保留率中位数 `0.273`，减半 `149/198`，显著反号 `26/198`，差速 MAE `45.499`。
- `_140633`：80 组大转弯，保留率中位数 `0.253`，减半 `60/80`。
- `_142207`：95 组大转弯，保留率中位数 `0.276`，减半 `75/95`。
- `_140027`：23 组大转弯，保留率中位数 `0.193`，减半 `14/23`，同时有较多反号。
- `_134318` 没有旧模型 `|d|>15` 的样本，不能用该运行证明转弯表现。

证据：`results/existing_array_metrics.json`；计算脚本 `scripts/analyze_existing_arrays.py`。

### 3.3 H2：新模型在开发集上会做大幅转弯，全局“均值回归”不能解释现场

开发验证集按真实标签分桶，差速保留率中位数如下（旧模型也在完全相同的 5,678 帧上回放）：

| 标签 `|d|` 桶 | 样本数 | 旧模型保留率中位数 | 新模型保留率中位数 | 新模型减半率 | 新模型差速 MAE |
|---|---:|---:|---:|---:|---:|
| 15–40 | 1,189 | 3.482 | 0.908 | 13.20% | 8.741 |
| 40–80 | 765 | 0.890 | 0.957 | 10.59% | 13.929 |
| >80 | 443 | 0.757 | 0.848 | 8.58% | 25.091 |

- 新模型在 `|target_d|>40` 的 1,208 帧上保留率中位数 `0.907`，减半 `119/1208`。
- 新模型全开发集差速 MAE `8.595`，旧模型为 `27.005`；旧模型不是普遍更准，而是响应特性不同。
- 原训练集大转弯标签并非全局罕见：`4721/22499=20.98%`；验证集为 `1208/5678=21.28%`。`|d|>80` 在原训练集有 1,312 帧，占 `5.83%`。

因此，单纯用“MSE 导致模型普遍不敢转弯”解释现场不成立。加权损失/重采样没有被当作已证实修复，也未执行。

### 3.4 H1/H3：大转弯标签按录像高度集中，现场最近邻正落在低大转弯覆盖区域

原训练集各录像包的 `|d|>40` 标签：

| 录像包 | 大转弯帧数 / 该包训练帧数 | 比例 |
|---|---:|---:|
| `record_data_26.5.10.zip` | 26 / 4,196 | 0.620% |
| `record_data_5.15.zip` | 3 / 4,506 | 0.067% |
| `record_data_5.16.zip` | 10 / 5,107 | 0.196% |
| `record_data_5.23.zip` | 2,774 / 5,043 | 55.007% |
| `record_data_5.30.zip` | 1,908 / 3,647 | 52.317% |

`5.23+5.30` 两包占全部大转弯训练标签的 `4682/4721=99.17%`。这解释了为什么“全局约 21%”与“某类现场场景缺少大转弯示范”可以同时成立。

特征结果：

| 特征 | 原验证集 NN 距离 P50 | 现场 NN 距离 P50 | 现场高于验证集 P95 | 域分离 AUC（按运行留出） | 距离预测塌陷 AUC |
|---|---:|---:|---:|---:|---:|
| conv0–2 空间均值 | 0.0352 | 0.2013 | 517/635 = 81.42% | 0.842–0.998；对照 0.488 | 0.627 |
| 倒数第二层 64 维 | 0.0340 | 0.1040 | 161/635 = 25.35% | 0.715–0.847；对照 0.481 | 0.497 |

最近邻使用原训练集拟合的标准化+32 维 PCA 和余弦距离；域分类按现场整 run 留出，原训练/验证组不混用。

关键反证与补充：

- 倒数第二层距离在验证集 P95 以内的现场大转弯帧，仍有 `98/128=76.56%` 塌陷；P95 以外为 `51/70=72.86%`。**距离本身不能解释全部塌陷。**
- 旧模型大转弯掩码内，倒数第二层最近训练标签 `|d|>40` 只有 `31/198=15.66%`。
- 塌陷帧的倒数第二层最近邻中，`5.16/26.5.10/5.15` 合计 `125/149=83.89%`，正是大转弯标签极少的三包。
- 倒数第二层最近邻标签与新模型差速的相关系数为 `0.820`，与旧模型为 `0.538`。在验证集 P95 以内，新模型到最近邻标签的差速 MAE 为 `10.46`，旧模型为 `43.66`；新模型更符合这些较小训练标签。
- 最近邻联系表显示，部分训练三摄与现场在蓝色赛道、黄线和视角上已经很相似，但标签差速仍明显较小；另一些最远的样本还包含人员、脚和锥桶等离群内容。两类情况都存在，不能只讲“亮度”或“陌生背景”。

证据：`results/label_distribution.json`、`results/feature_analysis01/`、`results/feature_response_stratification.json`、`closest_collapsed.png`、`farthest_collapsed.png`。

### 3.5 H3：标签定义/来源能确认到哪里

已核实：

- 新缓存标签是 `joystick.csv` 的原始左右轮数值，`labels_encoding=csv_raw`，没有本轮另做平滑或缩放；标签数值尺度与模型 `speed_raw` 对齐。
- 旧 NUC 实发使用 `speed_raw`，`(x-200)*1+200` 是恒等变换，中位数滤波值未用于发送。
- 旧训练候选代码允许按顺序读取 `joystick.csv` 或 `auto_data.csv`；`auto_data.csv` 可以是既有模型输出，不是独立驾驶真值。
- 旧训练候选代码使用 `INTER_AREA`，部署是 `INTER_LINEAR`；默认损失/增强配置也与新训练不同。**但默认配置和候选代码不能证明旧模型实际训练参数。**
- 配置中指向的 `runs/tricam_20260602_103109/pt/best.pt` 及训练目录当前不存在，无法确认旧模型用了哪些 ZIP、是否混入自蒸馏标签或实际 smoothing/loss。

所以，“新旧训练数据或标签来源不同”仍待确认；已证实的是**同一场景下，新旧模型响应不同，而且新模型更接近原训练标签所体现的小差速控制**。

证据：`__init__ (2)/data.py:65-83,222-226,268-295`、`__init__ (2)/config.py:60-67,105-151,180-182`、`ros_craic_car/src/base_control/src/base_control.cpp:178-212`、`pynq_ffn/docs/01_文件分析与迁移决策.md:41-52,110-130`。

## 4. 现场蒸馏微调：实施与失败验收

### 4.1 预注册设计

实验：`field_distill_mix01`，合同 `results/field_distill_mix01_contract.json`，训练前已固定，未根据留出集修改。

- 教师：旧模型在现场图上的原始输出，只作参照。
- 现场训练：`_134318 + _140027 + _142207`，481 组。
- 现场留出：完整 `_140633`，154 组；其中旧模型 `|d|>40` 为 80 组。
- 原训练标签：22,499 组；原开发验证：全部 5,678 组。
- 冻结 conv0–2 六个权重/偏置张量；seed 42，AdamW `lr=1e-4`、`wd=1e-4`，FP32、无增强。
- 每批 64 现场+64 原始，352 步/轮，固定 5 轮，固定取第 5 轮；没有挑最佳轮或第二组调参。
- 原门槛：开发集 raw/d/大转弯 d MAE 相对增幅均≤5%，新增反号/近直行均为 0；FP32 与准确整数前端分别计算。

3. 不在赛前尝试“全局乘一个差速系数”来掩盖问题。它会同时改变开发集、近直行和反号行为，且没有闭环证据。

### 5.2 数据优先的正式修复

1. **补采当前现场的代表性数据**，使用 `--save-every 1`，按完整运行/圈记录起止、接管、急停和是否成功，不只保留旧模型自动轨迹中的少量抽样。
2. 优先获取可信的人工/手柄大转弯标签，至少覆盖当前赛道两种转向、相似弯道、不同背景和相机异常分层。旧模型输出可以继续作为蒸馏参照，但只有在整圈表现确认后才可视为“可用教师”，不能当独立真值。
3. 保留 `_140633` 这类整 run 留出，再新增完全未参与选参的运行做最终离线测试。禁止随机按帧划分。
4. 按场景/录像段检查大转弯覆盖，而不是只看全局标签比例。若补采后开发集仍出现大转弯缩幅，再单独预注册加权损失或重采样实验；当前 H2 未支持直接加权。
5. 继续冻结 conv0–2 以避免改 `bit/params.json`。若充分数据证明冻结前端本身无法适配，再另立需要重新量化/系统构建的大阶段，不能作为赛前隐式改动。
6. 新候选必须重新完成：全部 5,678 开发帧、留出现场运行、FP32+准确整数前端、原有 5%/零新增事件门槛；失败即停止，不调参制造通过。
7. 只有离线门禁全部已验证后，才讨论单独授权的真实 PL 和闭环测试。闭环必须保留独立急停，记录接管/失败，不把离线教师一致性当安全证明。
