# KV260 三摄智能车设计报告（当前提交草稿）

日期：2026-10-28
赛道：2026 年 AMD FPGA 创新设计赛道 3.3 自主选题初级组
状态：基于现有源码和原始证据整理，未进行新的板卡或实车复验。

## 1. 选题背景与创新点

项目面向固定赛道三摄智能车，将原 NUC 上已经运行的视觉驾驶模型迁移到 KV260。原始 NUC 模型、预处理、相机顺序和输出语义作为黄金参考，STM32 继续负责电机执行。

当前方案的主要工作不是简单安装 PYNQ 或转发串口，而是：

1. 将前三层卷积量化为 INT8，保持与 ONNX Runtime 一致的中间量化、最近偶数舍入和饱和语义。
2. 在 PL 中实现三摄共享的三层卷积前端，利用并行乘加和片内特征缓存减少数据搬运。
3. PS 保留原图像预处理、后半段 Transformer/输出头、设备管理和安全控制，形成可回退的 PS+PL 数据路径。
4. 用逐层整数参考、HLS C 仿真、RTL 协同仿真、单 IP 实现和 KV260 真实 PL 回放建立分层证据，而不是只报告 bit 生成或 Overlay 加载。

## 2. 候选方案与取舍

早期方案把四个 FFN 层卸载到 PL。多轮真实板测均慢于纯 CPU，因此不再作为当前加速主线。该历史说明“算子能卸载”不等于“端到端有收益”，相关文件保留在远程历史分支，不与当前工件混用。

当前路线选择 conv0–2 作为硬件落点：这三层计算密集、接口紧凑，PL 输出特征显著小于输入图像；后半段仍由 ORT 在 PS 上执行，避免一次性迁移全部模型带来的开发和验证成本。

量化带来额外误差，因此不能只验证网络输出近似。当前工程同时保留整数参考、量化参数和 PS 后半段哈希，分别记录 PL 对整数参考、PL 对 CPU INT8、PL 对 CPU FP32 的差异。现场任务效果另作验收，不能用数值等价替代。

## 3. 系统架构与软硬件划分

系统图和异常路径见 [../docs/architecture.md](../docs/architecture.md)。PS 负责三摄采集、crop/resize/BGR2YUV、INT8 查表量化、PL 缓冲与寄存器、反量化、后半段 ORT 推理和 21 字节串口帧；PL 负责 conv0–2；STM32 负责电机执行。

PL 输入为 `int8[3][3][66][200]`，输出为 `int8[3][64][9][25]`。真实 KV260 板测已证明 PL 核进行实际计算，因此该功能不是转接板或纯软件替代的描述。不过，当前 PS+PL 端到端性能仍未超过 CPU INT8，不能宣称总体加速目标已经完成。

## 4. 通信协议、时间同步与异常处理

相机按 USB 物理口绑定左/前/右，不以 `/dev/videoN` 推断身份。每帧记录单调时钟、推理序号和发送序号，用同一帧关联输入新鲜度、PL/PS 分项和输出间隔。

串口为 115200、8N1，21 字节固定帧。非法速度拒绝编码，无 ACK 时只记录“主机写成功”。相机断流、帧龄超过 200 ms、串口写失败或推理异常时，程序设计为补停车帧并返回等待。PL 超时后不能假定硬件停止，不能立即释放或复用 DMA 缓冲。

这些安全行为主要来自源码和离线/限定板测；当前 PL 路线的实时相机、真实串口、电机和整车闭环仍未验收。

## 5. 实测结果

以下数据与 [../metrics/metrics.csv](../metrics/metrics.csv) 使用同一组证据。

### 5.1 正确性与实现

- HLS C 仿真：124 组，5,356,800 字节，0 差异。
- RTL 协同仿真：4 个完整三摄事务，172,800 字节，0 差异；120 帧全量 RTL 未执行。
- 单 IP OOC：100 MHz 目标，WNS +1.806 ns、WHS +0.035 ns，76,979 nets 全路由、0 error。
- 布线后资源：LUT 21,100（18.02%）、寄存器 22,784（9.73%）、RAMB36 95（65.97%）、URAM 26（40.63%）、DSP 788（63.14%）。
- OOC 有 122 个输入和 250 个输出缺外部 I/O delay 约束，不是整系统时序签核。

### 5.2 KV260 真实 PL

2026-10-21 一次真实下载，未写时钟，PL0 为 99.999 MHz。117 帧共 5,054,400 个输出字节，PL 对整数参考 0 差异；437 次 START 正常完成，最终 idle。

同进程 4 线程、300 次、warmup 20，不含 JPEG 解码：

| 路径 | P50 | P95 | P99 |
|---|---:|---:|---:|
| PS+PL 总时间 | 19.6545 ms | 21.4581 ms | 33.4207 ms |
| CPU FP32 总时间 | 25.5001 ms | 34.5349 ms | 51.7001 ms |

P50 加速比约 1.297 倍。PS+PL 分项 P50 为：查表预处理 5.2438 ms、PL 核 4.1608 ms、PS 后半段 9.2455 ms；其余时间包括缓存同步、反量化与调用开销。

另一轮纯 CPU 计时中，CPU INT8 整图 4 线程 P50 为 17.9221 ms，比 PS+PL 19.6545 ms 更快。两轮不是完全同进程 A/B，因此只作基线对照，不计算夸大的加速比；至少可以明确，**当前没有对 CPU INT8 的端到端加速结论**。

### 5.3 15 Hz 调度实验

2026-10-22 使用录像帧和已加载 Overlay，20 秒编码/调度 300 个速度帧，发送间隔 P50/P95/P99/最大为 66.80/68.23/82.79/86.24 ms；351 次推理总时间 P50/P95/P99 为 19.56/28.20/40.16 ms。该实验不含 JPEG 解码、实时相机和真实串口，不是实车 15 Hz 闭环。

## 6. 失败分析与当前边界

### 6.1 性能仍未超过最优 CPU 路线

PS+PL 相对 CPU FP32 有收益，但 CPU INT8 整图更快。后续优化应同时看预处理、PL 核、缓存同步、PS 后半段和端到端，不得只拿 PL 核 4.16 ms 宣称整帧加速。

### 6.2 新模型现场转弯效果失败

2026-10-27 离线诊断显示，在旧模型 `|d|>40` 的 198 组现场大转弯参照中，新 FP32 平均 `|d|` 22.413，保留率中位 0.273，149/198 减半，26/198 显著反号。当前证据更支持“特定现场场景缺少足够大转弯示范、场景—标签联合分布不匹配”，而不是单纯部署链路或亮度问题。

现场数据来自旧模型轨迹，没有新模型闭环数据，无法离线证明增大输出一定安全。当前不能安全替换旧模型 CPU 保底路线。详见 [../metrics/evidence/field_turning_diagnosis.md](../metrics/evidence/field_turning_diagnosis.md)。

### 6.3 尚未完成的验收

- 当前同源 PL 路线的实时三摄、真实串口、电机与固定赛道闭环。
- 120 帧全量 RTL、整系统时序签核、长时稳定、功耗和温度。
- 当前 STM32 固件身份、物理轮映射、断联和急停的隔离验证。
- 完整通用 PYNQ 技能包和正式版报告。

## 7. 从零复现说明

### 7.1 离线交付复核

在仓库根目录的 Bash 中使用 Python 3：

```bash
python metrics/scripts/verify_delivery.py
python host/deploy/make_bundle.py
```

前者验证清单、哈希、链接与大小；后者从当前目录生成带 MANIFEST 的车端 tar 包和 SHA-256。预期均退出 0；任何一步失败即停止。该过程不访问硬件。

### 7.2 HLS 与主机验证

源码、四组向量、量化参数和 `hls.cfg` 位于 `fpga/src/`。在具有 Vitis 2026.1 的工具机上，从 `fpga/src/build/` 按 [../fpga/src/README.md](../fpga/src/README.md) 依次执行 csim、csynth、cosim。任何一步非零或报告缺失都停止，不复用旧结果冒充新运行。

### 7.3 硬件部署

按 [../docs/hardware_setup.md](../docs/hardware_setup.md) 核对接线和供电，按 [../host/deploy/README.md](../host/deploy/README.md) 生成并校验安装包。安装、Overlay 下载、服务启动、串口和车辆动作是不同授权对象，不应由“离线校验通过”自动继续执行。

板上结果必须重新记录工具版本、模型/bit/HWH 哈希、相机顺序、线程、帧数、warmup、退出码和原始日志，并与 CPU 基线分开比较。

## 8. 大模型协作与技能沉淀

本工程使用大模型辅助源码分析、HLS 调试、证据分层、失败诊断和交付整理。协作原则要求保留失败结果、工具反馈和自我纠正，不把静态估计或 mock 写成板测通过。本快照保留了关键验证报告和现场失败分析。

完整通用 `skill/amd-pynq` 正文当前不在本地，只有客户端发现入口，因此本包只提供 [../skill/README.md](../skill/README.md) 的状态说明与复用索引，**不能声称完整技能包已交付**。

## 9. 结论

当前方案已经完成从 HLS 到 KV260 真实 PL 的计算链路，PL 数值正确且相对 CPU FP32 有一定收益；但相对 CPU INT8 仍未加速，现场新模型转弯效果也未达到可安全替换要求。项目当前最真实的结论是“硬件计算链路已验证，最优端到端性能与整车任务验收仍未完成”。
