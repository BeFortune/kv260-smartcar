# 面向低算力平台的视觉自动驾驶车设计报告

日期：2026-10-31
赛道：2026 年 AMD FPGA 创新设计赛道 3.3 自主选题初级组
验收口径：635 组整数参考全链离线仿真 + PL 模块 HLS/RTL 证据，不是板上或实车验收。

## 1. 选题背景与创新点

项目面向低算力平台的三摄视觉自动驾驶车，目标是在保留原图像预处理、相机顺序和输出语义的前提下，将驾驶网络前端卷积迁移到 PL，并由 PS 联合路标检测与控制策略输出安全控制。

当前唯一主方案为 **conv_front_int8 + PS partB + 真实 YOLO + 控制层 v2**。主要工作包括：

1. 用 INT8 三层卷积前端降低 PL 接口数据量，保留量化、最近偶数舍入和饱和语义。
2. PS 保留后两卷积、Transformer、输出头和真实 YOLO，避免把全部计算简单搬到 PL。
3. 用统一 v2 快照和状态机处理驾驶、路标、帧龄、故障与停车优先级，模型不直接写串口。
4. 用同帧全链验收替代“各模块分别正确就算完成”的判断，保留失败、反号和转弯不灵敏结果。

固定左 CSV 是独立开环保底附录，不与主链混写。

## 2. 此前方案与取舍

早期 FFN 卸载、原模型 128 通道候选和旧路标仲裁均已从最新快照移除，保留在 Git 历史和 PR 中。移除原因包括：端到端收益不成立、缺少新硬件证据，或不符合当前统一控制接口。

当前方案不把历史驾驶-only 的 PL 板测当作 YOLO+PL+PS 全链成绩，也不把固定左 98 行候选当作转弯问题已经解决。

## 3. 系统架构与软硬件划分

完整数据流见 [../docs/architecture.md](../docs/architecture.md)：

- **PL**：conv0–2，输入 `int8[3][3][66][200]`，输出 `int8[3][64][9][25]`。本次 635 组使用整数参考模拟其数值行为。
- **PS**：crop/resize/BGR2YUV、INT8 查表量化、反量化、partB 和真实 YOLO。partB 的后两卷积、Transformer 和输出头仍为 FP32。
- **控制层 v2**：验证驾驶与检测快照，统一处理红灯、行人、限速、横道、帧龄和故障锁存，产生唯一最终决策。
- **协议层**：把最终决策编码为 21 字节报文；本次不执行物理串口发送。

PL 的作用必须有实际计算和模块证据支持，不能用转接板、串口转发或软件 mock 冒充 FPGA 加速。当前全链失败也说明，单独证明一个 PL 核正确并不等于整机任务达标。

## 4. 接口、时间同步与异常处理

模型和工件哈希见 [../docs/interface.md](../docs/interface.md)。真实 YOLO 固定上游提交与 SHA-256，模型只有 10 类，没有锥桶类别。

每个样本关联三路抓帧时间、驾驶完成、YOLO完成和策略时间。v2 从原始抓帧时间计算帧龄，并拒绝未来、旧代、倒序、同序号内容变化、非有限和非法速度。当前 0.5 秒窗口是预先固定的离线诊断值，不是车辆安全阈值。

故障锁存后不能由后续正常帧、驾驶建议或绿灯自动清除。编码成功不等于 STM32 已接收，软件停车不等于电机已停止或独立急停已触发。

## 5. PL 模块实现与仿真

当前 HLS 源码、四组向量、bit/HWH 位于 `../fpga/`。已有模块结果：

| 阶段 | 结果 | 边界 |
|---|---|---|
| HLS C 仿真 | 124 组，5,356,800 字节，0 差异 | 只验证 conv0–2 |
| HLS 综合估计 | 412,297 cycles/三摄事务 | 静态估计，不是全链或板测 |
| RTL 协同仿真 | 4 个三摄事务，172,800 字节，0 差异 | 120 帧全量 RTL 未执行 |
| 单 IP OOC | WNS +1.806 ns、WHS +0.035 ns | 缺外部 I/O delay，不是系统签核 |
| 布线后资源 | LUT 21,100、FF 22,784、RAMB36 95、URAM 26、DSP 788 | 单 IP 实现结果 |

这些结果证明当前 PL 前端具有可复核的实现基础，但不能替代 YOLO+PL+PS 同帧全链。

### 5.1 驾驶通路的板测结果（2026-10-21，PL 模块级）

这一节只覆盖"三摄预处理 → conv_front_int8 → PS partB → 四路驾驶输出"这条通路，**不含 YOLO、control v2、报文编码和串口**。它与第 6 节的全链不是同一次运行，两者分母不同，不能相加、相除或互相替换。

上板条件：2026-10-21 一次真实下载，未写时钟，PL0 实测 99.999 MHz；437 次核启动正常完成，最终 idle。证据见 [../metrics/logs/pl_board_run01_report.json](../metrics/logs/pl_board_run01_report.json)。

| 项目 | 结果 | 口径 |
|---|---|---|
| 数值一致性 | 117 帧、5,054,400 输出字节，对整数参考 0 差异 | 录像回放，不是实时相机 |
| speed 对 CPU INT8 | 最大差 0.0180817 | 含量化差异 |
| speed 对 CPU FP32 | 最大差 5.2713 | 含量化差异 |
| PS+PL 总耗时 P50 / P95 / P99 / max | 19.6545 / 21.4581 / 33.4207 / 39.0185 ms | 同进程 4 线程、300 次、warmup 20、不含 JPEG 解码 |
| CPU FP32 总耗时 P50 / P95 / P99 / max | 25.5001 / 34.5349 / 51.7001 / 58.0461 ms | 同上 |
| 分项 P50 | 查表预处理 5.2438、PL 核 4.1608、PS partB 9.2456 ms | 其余为缓存同步、反量化与调用开销 |

P50 比值为 1.297，即海报上的"约 1.30 倍"。**这个倍数只对 CPU FP32 成立**：另一轮纯 CPU INT8 整图 P50 为 17.9221 ms，比本通路更快；两轮不是同进程 A/B，所以只作基线对照，不能相除。证据见 [../metrics/evidence/cpu_timing_run01.json](../metrics/evidence/cpu_timing_run01.json)。

边界：这是 PL 模块级的驾驶通路成绩，不是全链、不是实时相机、不是 15 Hz。

## 6. 635 组全链离线仿真验收

### 6.1 方法

集成工具为 `../host/app/tools/integrated_sim_replay.py`。对同一批 635 组图像实际执行：

```text
整数参考 PL -> 反量化 -> PS partB -> 驾驶输出
                              + 前视真实 YOLO
                              -> v2 决策 -> 21字节报文
```

输入包含 4 次运行，共 635 个唯一有序样本。模型、参数、源码和输入合同均记录 SHA-256。逐样本保存各阶段输出、检测、最终决策和报文，并独立重读复核。没有导入 PYNQ 或访问硬件。

### 6.2 覆盖与结果

- 635/635 样本实际完成，无缺漏、无额外样本，635 次整数参考核调用。
- 全部 21 字节报文独立复算一致，非有限和非法速度没有静默通过。
- 6 个真实 YOLO 红灯观测全部产生停车决定。
- 决策分布：普通驾驶 441、红灯锁存停车 152、driver_stale 42。
- **最终验收状态：失败。** 第 4 次运行首次出现 1 次 `driver_stale`，帧龄 0.5462195 秒，超过 0.5 秒诊断上限；故障随后锁存 42 tick。

42 是锁存 tick 数，不是 42 次独立超时。独立复核见 [../metrics/evidence/integrated_sim/independent_verification.json](../metrics/evidence/integrated_sim/independent_verification.json)，首次故障样本见 `fault_samples.json`。

### 6.3 离线耗时

本机 Windows 离线测量：整数参考驾驶总时间 P50 94.02 ms，YOLO P50 261.78 ms。驾驶分项 P50 为预处理 1.04 ms、整数参考核 91.33 ms、反量化 0.27 ms、partB 1.23 ms。

这些数字只描述本次主机和串行回放，不是 HLS、物理 PL、KV260、实时相机或 15 Hz 成绩。不能用异步想象或历史板测替换本次实际全链结果。

**检测频率为什么可以低。** 路牌是稀疏事件：635 组里只有 6 次红灯观测，绝大多数帧根本没有路牌。检测结果按事件锁存，控制层消费的是"最近一次有效路牌事件"，不要求每帧都有新检测。所以约 3.8 帧/秒（P50 261.78 ms）不会给速度通路增加逐帧负担——它跑在独立线程里，与驾驶推理并行，而不是串在 21 字节报文的生成路径上。代价是"看见路牌到产生决定"多出约 0.26 到 0.5 秒；配合 `confirm_frames=2` 与 `confirmation_max_gap=0.5 s`，两次确认约需 0.52 秒，要求路牌在视野中停留足够久。

这条推理有明确边界：本次 635 组回放输入的是**已保存的检测结果**，不是活循环中的实时检测；上述 0.5 秒窗口的余量在 KV260 的 ARM 核上会更紧张，必须实测后才能作为结论。

## 7. 反号与转弯不灵敏

### 7.1 保存手柄参照

在 5,678 组保存手柄指令上，Route B FP32 的强反号率为：`|d|>15` 时 28/2397（1.17%），`|d|>40` 时 20/1208（1.66%）。旧 NUC 分别为 1.54% 和 1.99%。这些是记录命令的一致性指标，旧模型训练集重叠未确认，不是独立实车正确率，也不证明两模型等效。

### 7.2 本次整数参考全链相对旧教师的分歧

| 旧教师差速掩码 | 样本数 | 强反号 | 幅度减半 | 绝对幅度保留中位 | 差速 MAE |
|---|---:|---:|---:|---:|---:|
| `|d|>15` | 352 | 89（25.28%） | 209（59.38%） | 0.3942 | 39.8805 |
| `|d|>40` | 198 | 27（13.64%） | 150（75.76%） | 0.2663 | 45.9958 |

**反号和转弯不灵敏仍是待优化问题。** 现场 635 组没有同步正确动作真值，所以这些数字只表示模型与旧教师的分歧，不能判断每一路谁对谁错，也不能写成“旧车也反号”或“转弯已修复”。结果见 [../metrics/evidence/integrated_sim/direction_metrics.json](../metrics/evidence/integrated_sim/direction_metrics.json)。

## 8. 固定左保底附录

固定左完整读取 98 行 `left.csv`，名义 10 Hz，表尾停车，不根据左右牌选路，不自动交回模型。35 项新测试和 16 个虚拟时序示例通过，11 种中止均不恢复。

它是开环保底，不执行驾驶模型或 YOLO，也不证明真实串口节奏、到达出口或闭环转弯能力。详见 [../docs/fixed_left_fallback.md](../docs/fixed_left_fallback.md)。

## 9. 复现说明

离线清单和 342 项保留测试可从仓库根目录直接复核。完整 635 回放需要原始图像合同、metadata 和固定身份的真实 YOLO；仓库不包含原始录像或第三方 YOLO。

具体环境、输入、命令、预期退出码和停止条件见 [../docs/reproduction.md](../docs/reproduction.md)。当前完整回放的预期结果为 635 组完成但验收失败，不能用调大帧龄窗口或覆盖旧证据制造通过。

## 10. 大模型协作与可复用经验

大模型辅助了代码分析、HLS/证据整理、集成适配、报告和交付校验。关键协作原则是：先固定输入与身份，保留失败和工具反馈，区分主机、整数参考、HLS/RTL、物理 PL 与实车，不能用后续成功覆盖此前失败。

可复用全链工作流位于 [../skill/README.md](../skill/README.md)，明确输入、步骤、输出、失效条件和本次发现的问题。交付脚本位于 `../metrics/scripts/`，`delivery_manifest.json` 记录逐文件来源、大小和 SHA-256。

## 11. 结论

当前方案已经具备 PL 前端模块证据和一套真正同帧执行的 YOLO+PL+PS 离线全链。635 组全部完成、报文全部合法、红灯全部停车，但 1 次输入过期导致验收失败；反号和转弯幅度不足也仍然存在。

因此，本报告结论是：**最新方案的离线全链已跑通并完成验收记录，但验收未通过，反号与转弯不灵敏仍待优化；HLS 全链、真实 PL、15 Hz、检测准确率和实车安全均未证明。**

后续优化优先级：

1. **检测器提速。** 把约 3.8 帧/秒提到 10 帧/秒以上，给 0.5 秒确认窗口留出余量。三条路按性价比排：降输入分辨率（640→320，计算量约降四倍，代价是小目标检出率）、INT8 量化、迁到 DPU。前两条是短期可做的，DPU 需要工具链与额外调试时间。
2. **提升卷积核吞吐。** 目标超过 CPU INT8 整图路线，而不是只相对 FP32 有收益。
3. **修正反号与转弯幅度**，并在有独立真值的条件下重新评估，不能用手柄参照代替。
4. **接入实时三摄、真实串口与整车闭环**，届时同时报告持续输出率与 P50/P95/P99 间隔。
