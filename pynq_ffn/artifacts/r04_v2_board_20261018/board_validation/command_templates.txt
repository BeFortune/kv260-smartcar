Scope and prerequisites
- Files created only below pynq_ffn/artifacts/r04_v2_board_20261018/board_validation/.
- No board/tool-server connection, PYNQ hardware import, programming, MMIO, camera,
  serial, vehicle action, firmware change or maintenance performed by this task.
- Main coordinator must review real Vivado implementation/timing/DRC reports and
  approve the exact new bit/HWH BEFORE independently programming the Overlay.
- This harness NEVER downloads an Overlay and NEVER writes PL/PLL clocks. It only
  reuses an already-programmed matching bitstream via Overlay(download=False).
- Host-file SHA + runtime bookkeeping are NOT FPGA configuration readback.
- Privileged AArch64 Linux is required for authorized workers. Board must be
  exclusively owned, no other kernel user/ROS/camera/serial jobs. Working sudo
  credentials are supplied interactively by the user, never by this script.
- Existing board Python must include NumPy/ORT/OpenCV/PYNQ. Prior successful board
  command explicitly set XILINX_XRT=/usr and venv PATH; no LD_LIBRARY_PATH or profile
  source was used. Verify the actual XRT/venv files first, do not infer reinstall.
- Harness passes the inherited explicit environment to all child processes and
  records XILINX_XRT, PATH, LD_LIBRARY_PATH, PYTHONUNBUFFERED. No source/profile.
- Templates use -B, NOT -I (which hides the sibling safety_gates import directory).

Actual stopping rules
- System confirmation/hash/model/runtime/ABI/reference/dataset/permission mismatch:
  fail, no next worker. Nothing auto-fixes or auto-downloads.
- Actual PL0!=100±0.5MHz: fail BEFORE backend/allocation/START. No DIV15 fallback,
  no new PLL permission inferred from the old retest. Main coordinator decides.
- Endcheck/raw clock drift/numerical mismatch: fail; cleanup only if known-complete
  and idle. A completed run does not establish continuous clock stability.
- Timeout/ambiguous AP_START write/poll error/SIGINT while inflight/poison/busy or
  unreadable cleanup state: failed_quarantined. All possible AXI buffers and owner
  process retained; no close/free/return/process exit/reset/reload. Even a later
  idle read cannot clear a poisoned backend. SIGTERM/SIGHUP ignored, quarantine
  SIGINT ignored. Parent waits indefinitely; it never terminate/kill/timeout.
- Quarantine is an intentional NON-EXIT state. Preserve terminal/process. Main
  coordinator must separately authorize and verify a hardware-safe recovery before
  any eventual termination. Never treat killing a process as cancelling an AXI
  master. Evidence disk full cannot make quarantine exit.
- SIGKILL, host shutdown, kernel OOM and physical power loss cannot be prevented by
  Python. Do not use supervisors/terminal tools whose stop semantics are unknown.
