# r04 v2 已上 KV260：正确性通过，加速目标失败

日期：2026-10-18。**本页性能来自真实 KV260 的 PS+PL 运行，不是仿真。** 使用离线录像，仍不是实时三摄、串口控制或实车任务。

## 1. 真正执行了什么

- 将已冻结 r04 v2 IP 集成为独立完整系统，Vivado 2026.1、K26、100 MHz 约束；实现/bitgen 前后门均通过：WNS +1.747 ns、WHS +0.010 ns、TNS/THS 0，97,862 条网络全部路由、路由错误 0，DRC 无 Error/Critical Warning。
- 与 r03 的 1,692 项 PS CONFIG 完全相同。控制 `0xA0000000`、六个 64 位指针、`num_tokens`、两个 64 位地址 m_axi、HP0 DDR 低/高段保持；不是 AXI-stream DMA 设计。
- 同次 bit/HWH/XSA 取回并校验，XSA 内 bit/HWH 与独立工件逐字节一致；系统交付 109 文件 SHA 复核。
- 只下载一次新 bit，使用官方父类 `Bitstream.download(overlay, overlay.parser)`，不执行会重设 HWH 分频的 `Overlay.download()`。没有写 PL/PLL 时钟、CPU 配置或启动固件。
- 板上真实 PL0 由寄存器 getter 得到 **99.999 MHz**，CPU 1333.32 MHz；编程前、独立编程后复核、计算前后，四路 PL、五个 PLL、ACPU 原始寄存器一致。不是示波器测频，也不是连续监控。
- 新核执行 1-token 冒烟、36 个单层真实输入/边界/权重轮换用例，随后 117 帧正式回归；共观察 **517 次软件 AP_START 写入**。它不是独立硬件周期计数器，但每次由真实后端等待完成、取回并核对结果。
- 正常结束先验证 `CTRL=0x4` idle，再关闭后端释放 buffer，最后清理 ORT 会话；无超时、无隔离保活事件。新核留在板上空闲，**没有回退到 r03**。

正式 `hls/ffn_accel.cpp/.hpp` 仍保留 r03；新系统采用 `hls/candidates/interleaved_r04/v2/`。板上新核与正式源码入口的角色不可混淆。

## 2. 同轮同条件性能

同一 KV260、同模型/117 帧录像、FP32、4 线程、预热 3 帧；三个模式分别运行于独立进程。golden 保持原 `spinning=None`，两条切图路径显式 `spinning=False`；生产 `Runtime.run` 未改。

| 模式 | 推理均值 | 推理 P50 | P95 | P99 | 最大 |
|---|---:|---:|---:|---:|---:|
| 完整图 CPU | 68.38 ms | 65.21 ms | 69.84 ms | 145.36 ms | 159.10 ms |
| 切图 CPU，关闭空转 | 76.54 ms | 74.87 ms | 88.24 ms | 114.96 ms | 118.69 ms |
| 新 r04 v2 PS+PL，关闭空转 | 171.85 ms | **170.03 ms** | 184.10 ms | 196.17 ms | 198.51 ms |

**新 PS+PL 的中位推理耗时为完整 CPU 的 2.607 倍、切图 CPU 的 2.271 倍。加速目标失败。**

`run_total` 包含原 Runtime 和 FFN 诊断复制，排除初始化与图像解码预处理。加入原图磁盘解码/预处理后的离线端到端 P50 为 CPU 91.99 ms、切图 CPU 100.86 ms、PS+PL 196.49 ms。

PS+PL 的 117 帧正式循环持续 30.309 秒：包含数值比较、NPZ 保存和证据 fsync 的持续输出率为 **3.860 次/秒**；只按 `run_total` 总时长计算为 **5.819 次/秒**。这些不是实时相机新鲜帧率，更不是车辆控制发送率。相邻完成间隔 P50/P95/P99/最大分别为 227.20/256.35/1593.06/2057.27 ms，包含证据写盘，不能把证据写盘尾部都归咎于硬件核。

## 3. 慢在哪里

对同轮逐帧样本求均值，PS+PL 每帧约：

| 串行组成 | 均值 |
|---|---:|
| PS 剩余子图计算 | 57.07 ms |
| 四次 FFN 准备（含权重/输入复制、同步与参数设置） | 16.79 ms |
| 四次真实核等待 | 87.93 ms |
| 四次结果读回 | 6.13 ms |
| 其余 Runtime/诊断等开销 | 3.93 ms |
| 合计 | 171.85 ms |

这是同一组样本的均值分解，不把各项中位数机械相加。

- 两个大 camera FFN：每层真实核等待约 **40.93 ms**，加准备与读回总后端耗时约 **48.09/47.96 ms**。同轮 CPU 上这两层的总 stage 耗时均值只有 **7.76/7.68 ms**。
- 两个小 cross FFN：每层等待约 **3.03 ms**，准备约 **4.15 ms**，后端合计约 **7.40 ms**；同轮 CPU stage 均值约 **0.46 ms**。即便 token 少，每次调用仍要付准备开销。
- CPU 与 PL 路径的 PS 剩余计算均值接近（57.69/57.07 ms）；本轮主要新增时间在 FFN 后端，而不是把四线程忙等问题又算成新核收益。

8-token 交错流水确实让新核比旧 PL 更有吞吐，但 **CPU 也在并行执行经过优化的矩阵运算**。目前新核本身仍慢于 CPU，调用/复制/同步还会进一步增加耗时；把旧瓶颈改善，并不自动意味着超过 CPU。

HLS 的 660-token **36.2066 ms 是静态工具估计**；本轮约 40.93 ms 是主机观察的硬件等待墙钟，包括实际执行、AXI 交互、轮询观察等边界。本轮没有独立硬件周期计数器和总线性能计数，不能断言差额全部来自 DDR、全部来自算核，或把墙钟直接当 RTL 周期。

旧 r03 的 PS+PL P50 372.22 ms 属于另一轮且未关闭相同 ORT 空转，不能将 372.22/170.03 称为纯新核 A/B 加速比。本轮选择结论以同轮 CPU 对照为准。

## 4. 数值正确性

- 单层 36 项最大绝对误差 **1.0431e-7**，小于 1e-4；另含一次 1-token 先行冒烟。
- 117 帧新 PS+PL 相对完整 CPU 的最大绝对误差：
  - `speed_norm`：1.4901e-7
  - `speed_raw`：0.0001220703125
  - `region_logits`：7.0781e-8
  - `region_probs`：1.4901e-8
- 四输出均通过 atol=1e-3、rtol=0，整数速度 **0 分歧**。
- 累积 FFN 切点最大误差 **1.7881e-7**；切点误差依据每帧原始在线比较记录，PL 切点数组未全部另存。最终四输出 NPZ 已独立重新载入比较。
- 同轮切图 CPU 与完整 CPU 的四输出恰好全部零差；这不推广为其他线程条件都逐位一致。

## 5. 加载警告没有隐藏，也没有重下载

一次下载完成后，`program01` 捕获 PYNQ 元数据缓存文件的唯一 `ResourceWarning` 并按安全门记录“失败”、退出码 1，零核启动。原记录保留。源码证据显示 `gen_cache()` 的 `pickle.dump(parser, open(...))` 未显式关闭文件。

随后在全新解释器里独立只读复核新 runtime/global state、bit/HWH SHA、时间戳、idle 和所有时钟 raw，`program_verified01` 退出码 0；未改 PYNQ、未抹除警告、未第二次下载。正式计算仅在该复核后开始，三个进程和父任务最终退出码均为 0。
