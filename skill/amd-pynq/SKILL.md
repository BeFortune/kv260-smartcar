# AMD PYNQ 技能路由

## 适用场景

需要在 PYNQ 的 PS（处理器系统）与 PL（可编程逻辑）之间建立可复核流程时使用。A/B/C 是换题目、换板卡仍可复用的方法；`cases/` 只解释本队配置。只做概念解释时读取对应小节，不因为加载技能就执行硬件命令。

## 输入 / 前提

- 有明确的阶段目标、授权范围和停止条件；先区分只读检查与会改变硬件状态的动作。
- 有可读取的源代码、工具/运行环境信息、参考输入输出和证据保存位置。
- 上板类任务另有匹配的 bit/HWH、实际寄存器表、缓冲区和恢复方案；缺失时停在板前，不猜常量。

## 使用方法

1. 环境、设备口位、依赖或时钟异常：读 [A 环境检查](modules/a_env_check.md)。
2. HLS 仿真、综合、RTL、OOC、系统实现或工件核对：读 [B 构建门禁](modules/b_hls_vivado_build.md)。
3. Python 启动核、缓存同步、超时、数值等价或性能验收：读 [C PL 调用与验收](modules/c_python_pl_call.md)。
4. YOLO、PL、PS 与控制策略的同帧离线全链：读 [E 集成仿真验收](modules/e_integrated_sim.md)。
5. 遇到报错或准备写报告：查 [D 踩坑清单](modules/d_pitfalls.md)，先匹配触发条件，再按最小顺序排查。
6. 只有明确处理本队硬件时才打开 [卷积前端案例](cases/kv260_conv_front_int8.md) 或 [车辆协议案例](cases/smartcar_protocol.md)；不要用案例替代通用核对。

## 输出

按模块生成带日期的检查记录、阶段报告、数值/性能对照或失败诊断。每条记录包含条件、退出码（适用时）、覆盖范围、证据路径和未执行项；不在技能入口复制另一份指标。

## 失效条件

板卡、器件、PYNQ 版本、IP ABI、地址位宽、DMA/m_axi 形式、模型精度或约束改变时，旧步骤的常量与结论失效。没有真实证据时，模板只能标“模板/未验证”；仿真、mock、主机 C++ 和 CPU NumPy 不能替代板上结果。

## 已验证效果

本入口本身只做路由，不新增硬件验证。大部分通用方法已在本队环境验证；当前可复核的技能证据和状态见 [技能 README](../../../skill/README.md) 与 [当前交付指标](../../metrics/metrics.csv)，完整范围以各模块的“已验证效果”为准。没有第二块板卡、干净环境或他人复现记录。

## 来源失败或观察

本队曾出现“数值正确、时序通过、bit 能下板，但端到端更慢”的结果，也遇到设备名漂移、时钟读数与设计不一致、XSA 误识别和缩小 RTL 范围等问题。因此入口强制按阶段加载、保留失败、分开正确性与性能，不允许用单一“完成”覆盖所有层级。
