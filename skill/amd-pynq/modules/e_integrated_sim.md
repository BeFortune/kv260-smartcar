# E：YOLO + PL + PS 同帧离线全链验收

## 适用场景

驾驶前端、PS 后半段、路标检测和控制策略需要按同一样本串联验收时使用。用于发现“模块分别正确，但全链因时序、身份或控制门禁仍失败”的问题。当前案例使用整数参考 PL，不是 HLS/RTL 或物理 PL 全链。

## 输入 / 前提

- 带唯一样本 ID、运行代号、图像和 metadata 哈希的输入合同。
- 同源整数参考、量化参数和 PS partB；固定身份的真实 YOLO 与类别映射。
- 显式策略配置和全新输出目录。诊断帧龄/确认窗口不能冒充车辆安全参数。
- 已有离线 Python 依赖；不需要也不允许用 PYNQ 或真实设备代替本步骤。

## 使用方法

1. 先跑小测试，覆盖正常驾驶、停车优先和非有限值拒绝。
2. 逐样本核对图像/metadata，保留原始抓帧时间，不用推理完成时间抹掉输入年龄。
3. 实际执行整数参考 PL、PS partB、真实 YOLO 和 v2，不能把保存的最终输出冒充重新推理。
4. 将最终决策编码为协议报文，逐样本保存各阶段输出、检测、决策和报文。
5. 独立重读输出，复核样本顺序、核调用序号、报文和原因计数。
6. 分开统计首次故障与锁存 tick，分开统计保存标签指标与模型间现场分歧。

## 输出

产生 `predictions.jsonl`、`summary.json`、`independent_verification.json` 和 `direction_metrics.json`。汇总必须包含样本覆盖、首次故障、锁存 tick、停车观测、离线分项耗时和未执行层级。

## 失效条件

整数参考不能升级为 HLS/RTL 或物理 PL 证据；稀疏样本不能证明连续实时行为；旧教师不是独立正确动作真值；软件停车和报文编码不证明 STM32 ACK、电机执行或独立急停。调大窗口或覆盖失败记录会使验收无效。

## 已验证效果

2026-10-31 本次 635/635 样本、635 次核调用和全部报文独立复核通过，但 1 次 `driver_stale` 使总验收失败，并锁存 42 tick；6 个红灯观测全部停车。证据见 [全链摘要](../../../metrics/evidence/integrated_sim/summary.json) 与 [独立复核](../../../metrics/evidence/integrated_sim/independent_verification.json)。

## 来源失败或观察

此前各模块已有独立证据，但没有同帧全链。首次集成后暴露出 1 次真实过期及后续锁存，同时保留了强反号和转弯幅度不足，说明全链验收不能由模块结果拼接或历史板测替代。
