# A：环境检查与排障（通用）

## 适用场景

在 PYNQ Linux 上开始 PS-PL 工作前，核对镜像、Python、设备身份、设备树/Overlay 状态和时钟读数；也用于处理导入失败、权限不足、依赖冲突和设备节点漂移。默认只做只读检查，不下载 Overlay、不加载设备树、不改分频、不打开相机或串口。

## 输入 / 前提

- 已确认执行机器、终端、用户和授权范围；保存一份带日期的检查目录。
- 已知目标板卡、镜像或启动介质、预期 Python 环境和配套 bit/HWH 来源；不知道就先记录未知，不猜默认值。
- 可读的系统信息、USB 物理拓扑、设备树状态、PYNQ 安装元数据和历史日志。
- 需要运行时读取时钟或 PYNQ 状态时，另行确认允许导入 PYNQ；这与默认环境检查不是同一授权。

## 使用方法

### 1. 先固定软件身份

在选定的 Linux 终端执行只读命令，并记录完整输出与退出码：

```bash
python3 --version
python3 -m pip show pynq
python3 -m pip check
uname -a
```

`pip show` 只证明所选解释器看到的包元数据；还要记录解释器绝对路径、虚拟环境和 `sys.platform`。不要为了“修好环境”先升级或重装依赖。PYNQ 的运行时导入检查单独进行，避免导入副作用混入默认检查。

### 2. 按物理口绑定 USB 设备

1. 记录 `lsusb -t`、厂商/产品 ID、集线器和物理口；用 `/dev/v4l/by-path/` 或对应的稳定拓扑链接找设备。
2. 对每个角色保存“物理口 → 稳定链接 → 当前节点”的映射，再核对图像/设备身份；不要把 `/dev/videoN` 或 `/dev/ttyUSB N` 当作持久身份。
3. 重新插拔或重启动后重新读取映射；旧节点名只能当历史现象，不能当新配置。

只读示例（设备不存在时记录缺失并停止后续依赖步骤）：

```bash
lsusb -t
ls -l /dev/v4l/by-path/
```

### 3. 分离设备树、Overlay 和时钟状态

- 加载前记录设备树型号、已有 Overlay/固件状态、IP 名单、控制地址、寄存器表和当前时钟；加载后也记录同一组字段。读取状态不等于授权加载。
- bit、HWH、XSA 必须按同源工件核对；加载目录只放运行时需要的配套文件，避免把归档文件误当输入。
- 时钟要读实际值并与设计约束比较，不能只看 HWH 标称值或旧日志。读取 `Clocks.fclk0_mhz` 等 API 前确认运行时授权；**改分频、PLL、设备树或启动文件属于硬件状态变更，必须单独授权**，本模块不提供默认修改步骤。
- 发现频率不符、IP 不 idle、身份哈希不符或状态不明时停止，不用反复下载来“碰运气”。

### 4. 导入、权限、依赖故障的最小顺序

1. 确认实际执行的是哪一个 Python/ pip，检查版本和包是否属于同一环境。
2. 保留首个真实异常和退出码，再查环境变量、动态库路径、设备节点权限和用户组；不要先换模型或核。
3. 检查工具可执行文件是否是健康实体（例如包装脚本是否段错误），用同环境的最小 `--version` 验证。
4. 只有前述身份和权限均明确后，才做单独的 Overlay 或硬件测试；每一步保存前后状态。

## 输出

生成 `environment_YYYYMMDD/`（名称可调整）下的文本/JSON 记录：机器与系统、Python/包版本、USB 物理映射、设备树/Overlay 状态、实际时钟、命令与退出码、首个错误、未执行项。输出应足以让另一人判断“环境可用”还是“阻塞”，而不是只有一张成功截图。

## 失效条件

更换镜像、解释器、PYNQ 版本、USB 拓扑、设备树、Overlay 或 board preset 后，旧映射和状态全部需要重核。没有稳定物理口、权限、设备树或时钟证据时，不能推断 PL 可用；不能用主机包版本、mock 或历史板测代替当前环境。任何自动修复、安装、重启、刷写和硬件写入都超出本模块默认范围。

## 已验证效果

- 2026-10-22，本队按 USB 物理口重新核对设备映射，配置证据见 [硬件搭建](../../../docs/hardware_setup.md) 与 [口位配置](../../../host/app/ps/camera_ports.json)；历史记录同时保留少量丢帧，不能宣称链路完全可靠。
- 2026-10-31 当前全链为离线整数参考，635/635 样本与报文复核通过，1 次过期导致验收失败并锁存 42 tick，见 [全链摘要](../../../metrics/evidence/integrated_sim/summary.json)。当前快照不包含真实 PL 全链证据；历史驾驶-only 读数只留在 Git 历史/PR。
- 本模块的跨板、干净环境和他人复现：未执行；没有把上述单次观察包装成通用复现。

## 来源失败或观察

历史排障出现过三类易误判现象：设备节点编号变化导致接错输入；加载目录中的 XSA 触发 PYNQ 文件类型误判；非登录 shell 缺少运行环境或工具包装脚本异常，表现为导入/合成失败。另有实际时钟与设计目标不一致的记录。教训是先固定身份、读真实状态、保留首个错误，再决定是否进入会改变硬件的步骤；不要用重装、反复下载或猜频率掩盖根因。
