# B：HLS/Vivado 构建与产物核对（通用）

## 适用场景

从 C/C++ HLS 核到 RTL、IP、Vivado 实现和 bit/HWH/XSA 交付时使用。重点是每一阶段的通过判据、约束边界和工件同源，而不是“命令返回 0 就全部完成”。本模块的方法可换核、换板卡；器件示例仅是示例。

## 输入 / 前提

- 固定的 HLS 源码、testbench、配置文件、参考向量和预期输出；每轮使用新的 work/record 目录。
- 目标器件、目标时钟、工具版本、许可证/器件支持和可写构建目录已核对。
- 有系统级约束、接口/地址图和导出脚本（若进入 Vivado）；没有把旧 bit、旧 HWH 或其他候选核混入本轮。
- 本例曾使用部件号 `xck26-sfvc784-2LV-c` 和 10 ns（100 MHz）目标；这是专用配置例子，换板必须重新查询，不是通用默认值。

## 使用方法

### 1. 先过工具与配置门禁

1. 用实际完整路径核对 `vitis-run`、`v++`、`vivado` 的版本和帮助；记录许可证与器件查询的真实结果。
2. 在配置中核对 part、顶层函数、源码/testbench 相对路径、目标周期和地址位宽。目标周期只是约束，不是实测频率。
3. 任一前置查询失败、配置路径不存在或许可证/器件不被当前进程接受，就停止；不要把后续“未执行”写成失败或成功。

### 2. 按 csim → csynth → cosim 顺序执行

| 阶段 | 必须看到的通过证据 | 不能据此声称 |
|---|---|---|
| HLS C 仿真（csim） | 进程 exit 0；testbench 全部声明用例执行；参考比较通过；输出数量、误差阈值和无跳过记录清楚 | RTL、时序、板速或真实 PL |
| C 综合（csynth） | exit 0；报告实际生成；读取 latency、interval/II、资源估计和估计时钟 | 实现时序、系统吞吐或端到端延迟 |
| RTL 协同仿真（cosim） | exit 0；RTL/Verilog PASS；C post-check 通过；记录事务数、覆盖输入和输出字节 | 未覆盖边界、全量 RTL 或板上性能 |

每轮保留命令、工作目录、源码/配置哈希、日志和报告。若为了时间缩小 cosim，必须先写范围，事后按实际完成事务记账；主动中止或只完成一部分不能记 PASS。

### 3. 分开看 OOC 与系统实现

- **单 IP OOC**（out-of-context，脱离系统上下文实现）只检查 IP 在给定约束下的内部综合/布局布线。缺外部 I/O delay、未接 PS/互连或没有系统约束时，不是系统时序签核。
- **系统实现**还要有完整 PS/PL 设计、地址/复位/时钟连接、系统约束、实现后报告和导出工件。不能把 OOC 的 WNS 直接贴到整板。
- 时序至少读 WNS（最差建立裕量）、WHS（最差保持裕量）、TNS/THS（总负裕量）；通常要求 WNS/WHS ≥ 0、TNS/THS = 0，但仍要看约束完整性和报告范围。
- 路由表核对可路由与完全路由的 nets、未路由/错误数；资源表按阶段读取 LUT、寄存器、BRAM/URAM、DSP 的 used/available/比例。资源多不等于性能快，估算资源也不等于 post-route 资源。

### 4. 核对 bit / HWH / XSA 同源

1. 对最终交付文件逐字节计算 SHA-256，记录文件大小、导出 run 和源配置哈希。
2. 检查最终 bit 与完成实现 run 的 bit、XSA 内嵌 bit 是否一致；从同一 XSA 选取正确顶层 HWH，再核对其 IP 名、寄存器偏移、位宽和地址映射。
3. 运行包、板端部署记录和报告引用同一组哈希；任何重新综合、重新实现或改约束都开新一轮，不能手工改清单哈希凑一致。
4. XSA 仅作追溯时也要标明是否随包交付；没有文件本体就只写“哈希记录”，不能说已提供 XSA。

## 输出

输出按阶段分开的 `build_record.json` 或等效报告：工具/许可证/part、配置与源码哈希、csim/cosim 覆盖、csynth 估计、OOC/系统时序、路由、资源、导出工件哈希、退出码和未执行项。报告能回答“哪一个核、哪一组约束、哪一次实现、哪一份证据”。

## 失效条件

工具或器件不受支持、报告缺失、源/配置哈希改变、约束不完整、WNS/WHS/TNS 不达标、存在未路由网络、cosim 范围不足或 bit/HWH/XSA 来源不一致时，对应阶段不能通过。缺外部 I/O delay 的 OOC 不能称系统签核；单事务冒烟不能称全量 RTL；bit 生成不能称 Overlay 已加载或 PL 已加速。

## 已验证效果

- 2026-10-20 当前核证据：HLS C 124 组、5,356,800 字节、0 差异；RTL 4 个完整事务、172,800 字节、0 差异；csynth 静态估计 412,297 cycles/事务。见 [分层报告](../../../fpga/report/hls_fixed_acceptance01.json)。
- 同报告的单 IP OOC 在 10 ns 目标下 WNS +1.806 ns、WHS +0.035 ns、76,979 nets 全路由、0 routing error；122 个输入和 250 个输出缺外部 I/O delay，**不是系统签核**。120 帧全量 RTL、post-route 功能仿真和系统实现均按报告标未执行。
- 从零独立重建、第二块板卡复现：未执行；本模块只把已发生的分层结果转成可复用门禁。

## 来源失败或观察

历史构建曾先遇许可证失败，又遇“进程 exit 0 但目标器件查询无匹配”；这说明退出码不能替代门禁。另有长事务 RTL 因耗时主动中止、只保留小范围冒烟，以及候选核负 slack 后停止的记录。由此形成“先查工具/part、分阶段留证、明确缩小范围、OOC 与系统分开”的规则，而不是把旧报告拼成一条成功链。
