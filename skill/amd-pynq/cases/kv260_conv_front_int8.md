# 案例：KV260 三层 INT8 卷积前端

**以下为本队实测配置，换车或换板不可直接套用。** 当前主线是 `kv260car + conv_front_int8`，PL 执行原模型 conv0–conv2；本案例不是早期 FFN 卸载方案，也不提供默认上板授权。

## 适用场景

只用于复核本队 KV260/PYNQ 的 PS+PL 数据流、寄存器接法、数值证据和性能边界。换模型、换量化参数、换 IP、换板卡或换摄像头接线时，必须重新建立契约，不能复制地址和哈希。

## 输入 / 前提

- 板卡为 KV260/K26，HLS 器件配置为 `xck26-sfvc784-2LV-c`；运行时使用与本次 bit/HWH 同源的工件。
- 输入是三幅按左、前、右排列的 `uint8 BGR 640x480` 图像；每幅裁剪 `[150:479, 0:640]`，双线性缩放到 `200x66`，BGR→YUV、CHW，再查表量化。
- PL 输入连续 `int8[3][3][66][200]`，118,800 字节；输出连续 `int8[3][64][9][25]`，43,200 字节。输出用 `(q + 18) * 0.0806707814335823` 的 float32 表反量化后交给 PS 后半段。
- 有整数参考、`params.json`、后半段 ONNX、635 组保存样本、真实 YOLO 和 v2 配置；实时相机、物理串口、电机和实车不在已有验证范围内。

## 使用方法

1. **先核身份。** 运行前核对下表 SHA-256；bit/HWH/模型/参数任一不符就拒绝运行，不能换成历史 FFN 工件。

   | 工件 | SHA-256 |
   |---|---|
   | bit | `8ab0f411cc3ddee74045a753b379d265a121871dc656a53ef25b7c2edfe8da24` |
   | HWH | `c2b5c8138087c8e398d509df40e1c854311ebcca249f7a0e232c107d8db6d067` |
   | PS 后半段 ONNX | `61bcec8f01ffca61ecc611f12bdf61a177f8ee0e9dc0febd256e02b8132cecdb` |
   | params | `889703bc0ea80da1a1f49f647c11714b249ee1eaea3149894f35dbbf4eb86a3f` |
   | 整数参考 | `02feef12ea147f5b772a726ebd3c90d5f1e66bd33ff9fcefa50c3618a040edb4` |

2. **按本核 ABI 核对寄存器。** IP 名为 `conv_front_int8_0`，控制地址预期 `0xA0000000`，采用 `ap_ctrl_hs`：

   | 寄存器 | 偏移 | 用法 |
   |---|---:|---|
   | CTRL | `0x00` | bit0 START、bit1 DONE、bit2 IDLE |
   | `in_r` 低/高 32 位 | `0x10` / `0x14` | 输入缓冲 64 位设备地址 |
   | `out_r` 低/高 32 位 | `0x1c` / `0x20` | 输出缓冲 64 位设备地址 |

   这些偏移只对本组 HWH 有效。启动前确认 idle；写输入后 `flush`，写 START，等 DONE 后 `invalidate`，再读输出。超时不代表硬件停止访问内存，不能立即释放或复用缓冲。

3. **按层级验收。** 先跑 HLS C，再跑明确事务范围的 RTL 协同仿真，再看单 IP OOC；真实板测只使用匹配工件和录像输入。数值比较与性能比较分开，性能同时记录预处理、flush、核等待、invalidate、反量化、PS 后半段和总耗时。
4. **报告实际边界。** 2026-10-22 的调度实验只使用已加载 Overlay 和录像，不重新下载、不含实时相机/JPEG 解码/串口；不能把它写成实时整车结果。详细接口以 [interface.md](../../../docs/interface.md) 和当前源码为准。

## 输出

- PL 输出为上述 43,200 字节特征，PS 继续后半段推理并产生左右速度语义；无 ACK 时不能把输出称为电机已执行。
- 每层记录输入/参考、样本数、检查字节数、误差、退出码和证据路径；性能记录分位数、持续率、线程、warmup、测试时长和排除项。
- 本案例引用的机器证据在 `kv260-smartcar-submission/metrics/`，构建入口在 `kv260-smartcar-submission/fpga/src/`。

## 失效条件

任何哈希、张量形状、裁剪/缩放、相机顺序、量化常数、IP ABI、地址或时钟条件改变，本案例都不能直接套用。OOC 缺外部 I/O delay 时不能称系统时序签核；4 事务 RTL 不能称 120 帧全量 RTL；真实 PL 数值正确不能推出实时三摄、串口、电机、长时稳定或实车任务已验收。

## 来源失败或观察

早期 FFN 路线曾数值正确且能下板，却端到端慢于 CPU；迁移到本案例后仍发现“相对 CPU FP32 有收益”不等于“超过 CPU INT8”。因此保留两条对照线，并把 PL 核等待（P50 4.1608 ms）与包含 PS 剩余计算的总耗时（P50 19.6545 ms）分开。当前案例的价值是有真实 PL 计算贡献的可复核基线，不是宣称已完成整车或最优加速。后续努力方向是接入实时链路并缩小对 CPU INT8 的端到端差距；这些目标不改变当前未执行或失败状态。
