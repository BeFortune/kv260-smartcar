# 案例：三摄到 21 字节串口再到 STM32

**以下为本队实测配置，换车或换板不可直接套用。** 本文只做源码/离线报文说明和安全边界记录，不提供默认打开串口、发送电机命令或实车测试授权。

## 适用场景

只用于理解本队 KV260 PS 输出到 CH340 UART、再到当前分析的 STM32 接收格式。它不构成通用串口协议；最新固件和独立急停按用户确认记录，本轮未独立核验烧录内容或触发效果。物理轮序和断联停车不纳入本轮验收。

## 输入 / 前提

- 已核对 NUC 黄金参考的调用顺序和编码语义：自动路径方向标志固定为 ASCII `1`；手动路径发送速度绝对值，非负标志 `1`、负数标志 `0`。不要按口述自行翻转。
- 当前接法记录为 115200、8N1、3.3 V TTL；开发板与车分别供电，转换器 GND 接 STM32 GND，TX 接 PA3、RX 接 PA2，不接转换器 VCC。
- 用户于 2026-10-30 确认：车上固件为最新版本，速度单位为转每分钟（rpm），有独立急停；本轮不展开物理轮序，也不评估断联停车。上述是用户确认的配置与范围，不是本轮重新烧录、标定或急停实测。
- 本轮只做离线预览；任何实车动作仍需单独现场授权。若进入实车测试，驱动板零输入行为按现场安全流程核对。

## 使用方法

### 1. 按 USB 物理口识别，不按编号猜测

| 角色 | 物理口 | 备注 |
|---|---|---|
| 左相机 | `1-1.2.1` | icSpring `2993:0858`；历史压测有少量持续丢帧 |
| 前相机 | `1-1.4.2` | ARC USB 2.0 Camera `05a3:9230` |
| 右相机 | `1-1.4.1` | icSpring `2993:0858` |
| CH340 串口 | `1-1.2.3` | `1a86:7523`，接扩展坞 A 的 3 号口 |

两个 Genesys `05e3:0610` 集线器分别位于 `1-1.2` 与 `1-1.4`。模型输入顺序固定为左、前、右；`/dev/videoN` 和 `/dev/ttyUSB0` 不是持久身份。配置源为 `kv260-smartcar-submission/host/app/ps/camera_ports.json` 与 `serial_port.json`。

### 2. 离线构造并检查 21 字节帧

串口参数为 **115200、8 数据位、无校验、1 停止位、无硬件流控**。每帧前 19 字节为 ASCII，末尾是两个原始 `0xFF`，不能额外添加换行：

| 字节位置（从 0 起） | 内容 |
|---|---|
| 0..2 | `%@1` |
| 3..5 / 6 | 左速度三位十进制 / 方向标志 |
| 7..9 / 10 | 左速度三位十进制 / 方向标志 |
| 11..13 / 14 | 右速度三位十进制 / 方向标志 |
| 15..17 / 18 | 右速度三位十进制 / 方向标志 |
| 19..20 | `0xFF 0xFF` |

自动路径四组依次为左、左、右、右，标志均为 `1`。当前编码接受 0–999 的左右速度，浮点向零截断；负数、超范围、NaN/Inf 拒绝编码，不写入三位字段。停车帧为四组 `000`、标志均为 `1` 和相同包尾。例如只作离线展示的停车 ASCII 前缀是 `%@1` 后接四组 `0001`，再接两个原始 `FF`；这不是可直接发车的命令。

### 3. 只做离线预览，分清写入与执行

1. 在离线编码器中检查有限值、范围、截断、字段宽度、总长度 21 和包尾；保存 ASCII/hex 预览与输入序号。
2. 真实发送前按现场流程核对最新固件、接线、rpm 量程和独立急停，并取得现场逐项授权；本轮不评估断联停车，不展开物理轮序。当前任务不执行这些动作。
3. 无命令 ACK 时，`serial.write` 或日志只能证明主机尝试/完成写入，不能证明 STM32 收到完整帧或电机执行。分别记录发送率、新推理率、输入帧龄、旧结果重发和错误，不能用重发凑 15 Hz。

## 输出

输出离线报文预览、长度/字符/范围检查结果和带时间戳的调度日志；日志应关联输入序号、推理序号和发送序号。当前不产生车辆动作，不把停车帧文本当作已验证的物理制动。

## 失效条件

换固件、换接线、换 USB 口或改变速度语义时，本文配置失效。短帧、非法字符、无校验和、无 ACK、陈旧帧、负值/超范围等仍可能使控制不安全；断联停车不纳入本轮评估，主机停止发送不等于已验证物理停车。任何实时相机、串口、电机或实车结论都不能由离线预览推出。

## 已验证效果

- 源码层面已核对 NUC 自动/手动方向编码和 21 字节布局；这属于黄金参考/静态接口核对，不是当前车辆固件验收。依据：`docs/agents/interface.md`、`kv260-smartcar-submission/docs/interface.md`。
- 2026-10-31 当前 635 组全链实际完成，全部 21 字节报文独立复算一致；1 次 `driver_stale` 导致验收失败并锁存 42 tick，6 个红灯观测全部停车，证据为 [全链摘要](../../../metrics/evidence/integrated_sim/summary.json) 与 [独立复核](../../../metrics/evidence/integrated_sim/independent_verification.json)。**没有真实相机、物理串口或电机**。
- 用户已于 2026-10-30 确认最新固件、rpm 单位和独立急停；本轮未重新烧录、标定或触发急停。当前 PL 路线的实时三摄、真实串口、电机和实车任务：**未执行**；断联停车不纳入本轮范围。

## 来源失败或观察

源码核对曾发现接收路径没有可信的命令 ACK，固定下标解析和缓冲复用使短帧可能读到陈旧尾部，且所查通信路径未见超时清目标逻辑；本轮按用户决定不评估断联停车，因此这些只保留为历史边界，不列本轮交付缺项。速度单位现按用户确认为 rpm，但不把源码量纲分析改写成实测标定。由此本案例只保留与 NUC 一致的离线编码语义，不擅自修改 STM32 或车辆行为。
