# 硬件搭建、接线与供电

## 1. 已核对的平台

- 板卡：KV260 / K26，HLS 配置器件为 `xck26-sfvc784-2LV-c`。
- 三路 USB 相机，按 USB 物理口识别，不依赖会变化的 `/dev/videoN`。
- USB 手柄接收器：`413d:2104`。
- UART 转换器：CH340，`1a86:7523`。
- STM32 继续执行电机控制。

## 2. 2026-10-22 核对的 USB 接法

两个 Genesys `05e3:0610` 集线器分别接 KV260 的 `1-1.2` 与 `1-1.4`：

| 设备 | 角色 | 物理口 |
|---|---|---|
| icSpring `2993:0858` | 左相机 | `1-1.2.1` |
| ARC USB 2.0 Camera `05a3:9230` | 前相机 | `1-1.4.2` |
| icSpring `2993:0858` | 右相机 | `1-1.4.1` |
| CH340 `1a86:7523` | STM32 串口 | `1-1.2.3` |

左相机在历史压测中有少量持续丢帧记录，不能当作链路已完全可靠。机器配置源文件为 `host/app/ps/camera_ports.json` 和 `serial_port.json`。

## 3. UART 接线与供电

用户在 2026-10-22 确认 TTL 为 3.3 V：

- 开发板与车各自供电。
- 转换器 GND 必须接 STM32 GND。
- 转换器 TX 接 STM32 PA3，RX 接 PA2。
- 不接转换器 VCC。

不要在未核对当前固件、物理轮子映射、速度范围、断联停车和急停前把报文发到实车。源码中的停车逻辑不等于整车安全已验证。

## 4. 上电与启动顺序

1. 先核对接线、共地、相机口位和车辆处于安全隔离状态。
2. 核对 bit/HWH/模型哈希；Overlay 下载属于硬件状态改变，需单独授权。
3. PL 自检通过后再检查手柄、相机和串口；设备不齐不应进入控制。
4. 手柄 Back 才开始；右摇杆按下用于立即停车并回等待。
5. 正式实车测试前，先做不发串口的隔离回放，再做架空/限功率等分阶段测试。具体车辆动作由现场负责人逐项确认。

## 5. 尚未确认

- 当前车上 STM32 固件是否就是仓库分析的版本。
- 四个逻辑电机与物理轮子/编码器的对应、速度单位和允许范围。
- 实车断联、急停和驱动板零输入行为的隔离验证。
- 固定赛道圈数、终点、碰撞/出界判据和最终计时规则。

这些缺项阻塞当前 PL 路线的实车验收，不能用离线回放代替。
