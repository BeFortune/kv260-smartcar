# 最新系统架构与数据流

## 主方案

```text
左 / 前 / 右三摄保存原图
        |
        v
PS 预处理：crop、resize、BGR->YUV、INT8查表量化
        |
        v
PL：conv_front_int8 三层卷积（本验收用整数参考模拟）
  int8[3][3][66][200] -> int8[3][64][9][25]
        |
        v
PS：反量化 + partB（conv3-4、Transformer与输出头）
        |                         前视原图
        |                              |
        |                              v
        |                    真实 YOLO ONNX（CPU）
        |                              |
        v                              v
DriverSnapshot                 SignSnapshot
        \                              /
         \                            /
          \                          /
           -------- 控制层 v2 --------
                       |
                       v
             最终速度 / 停车决定
                       |
                       v
               21字节报文编码
```

- **PL（可编程逻辑）**：只承担 conv0–2。当前 635 组验收使用与其数值契约一致的整数参考，不是 HLS/RTL 或物理 PL。
- **PS（处理器）**：负责预处理、反量化、partB 和 YOLO。partB 不是整个网络 INT8，后两卷积、Transformer 和输出头仍为 FP32。
- **控制层 v2**：验证两类快照的代号、序号、时间和健康状态，统一处理驾驶、红灯、行人、限速、横道与故障；模型不直接写串口。
- **固定左附录**：独立开环 CSV 播放器，不参与上述 635 主链，也不根据路牌选路。

## 时间与故障

每个样本记录三路抓帧时间、驾驶完成时间、YOLO完成时间和策略时间。v2 从原始抓帧时间计算帧龄，不用推理完成时间抹掉输入年龄。当前 0.5 秒窗口是预先固定的离线诊断值，不是车辆安全参数。

任一结果过期、未来、旧代、同序号内容变化、非有限或速度非法都会拒绝。故障锁存后不能由后续正常帧或绿灯自动清除；需要新代号显式重建链路。

## 为什么保留 PL

PL 的卷积前端有独立 HLS C、RTL 和 OOC 模块证据，也有历史驾驶-only 的真实计算证据；但本报告不以这些历史结果替代当前 YOLO+PL+PS 全链。当前全链失败说明仅让各模块分别正确还不够，输入新鲜度、PS 剩余计算、YOLO负载和控制时序必须一起验收。
