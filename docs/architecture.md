# 系统架构与数据流

## 1. 软硬件划分

```text
三路 USB 相机（左 / 前 / 右）
          |
          v
KV260 PS：取帧、帧龄检查、crop/resize、BGR->YUV、INT8 查表量化
          |
          v
KV260 PL：conv_front_int8，三层 INT8 卷积
  输入  int8[3][3][66][200]   118800 bytes
  输出  int8[3][64][9][25]     43200 bytes
          |
          v
KV260 PS：反量化 + ONNX Runtime 后半段 + 左右速度输出
          |
          v
21 字节速度帧 -> CH340 UART -> STM32 -> 电机执行
```

- **PS（Processing System，处理器系统）**：负责设备管理、原模型一致的图像预处理、数据搬运、PL 调度、后半段推理、报文编码与故障处理。
- **PL（Programmable Logic，可编程逻辑）**：实际执行 conv0–2，不是转接板或串口转发。2026-10-21 的 117 帧板测证明其输出与整数参考逐字节一致。
- **STM32**：保持原有电机执行分工。KV260 侧源码不能证明当前车上固件版本和物理轮子的映射已经验收。

## 2. 为什么使用 FPGA

前三层卷积计算密集且数据布局固定，适合用并行乘加和片内特征缓存实现。当前核把三摄特征图保留在片内，PS 只传入量化图像并取回压缩后的特征。

实测 PL 核等待 P50 为 4.16 ms；包含预处理、搬运、反量化和 PS 后半段后，PS+PL P50 为 19.65 ms。它相对同轮 CPU FP32 25.50 ms 有约 1.30 倍收益，但仍慢于另一轮 CPU INT8 整图 17.92 ms。因此，**PL 有真实计算贡献，不等于已经获得对最优 CPU 路线的端到端加速**。

## 3. 数据与时间边界

每帧关联三摄输入、推理序号和输出发送序号。车端程序按 USB 物理口识别相机，输入顺序固定为左、前、右；三路帧龄超过 200 ms、断流、推理错误或串口写失败时，设计行为是补停车帧并回到等待状态。

需要分别测量：报文发送频率、新推理完成率、输入帧龄、PL 核时间、PS 剩余计算和端到端延迟。2026-10-22 的 15 Hz 实验只覆盖录像输入的推理与编码调度，不证明实时传感到物理响应达到 15 Hz。

## 4. 异常处理

- 模型、参数或 bit/HWH 哈希不一致：拒绝运行，不自动换用其他工件。
- PL 启动前不是 idle：拒绝启动。
- PL 超时：标记 `hung`，不得把“超时”当作 AXI master 已停止；持有缓冲的进程按设计停住，恢复需另行处理。
- 相机/手柄/串口不齐：不进入运行；手柄 Back 才开始，右摇杆按下或关键设备断开时停车。
- 非法速度（负数、超过 999、NaN/Inf）：拒绝编码，该帧不发送并记录事件。
