# YOLO 控制层 v2：2026-10-30 离线候选

## 设计

v2 将驾驶和 YOLO 计算放入独立 CPU worker，由控制状态机统一决定输出，再由唯一 Sender 写入。模型不直接拥有串口。红灯/行人停车、限速、横道和岔路意图都有显式状态；锥桶不在范围内，左右牌只表示支路意图，不直接变成轮速。

旧 `--roadsign-config`、同步 `CarLoop` 和默认车端路径未改，也没有新增可直接开相机或串口的 v2 实车入口。

## 已验证

- 最终新测试 59 项、旧路标/仲裁/CarLoop/主入口定向回归 83 项，均 0 失败、0 跳过。
- 真实 spawn 子进程受控阻塞时，控制 tick 仍可执行停车；释放后 join 成功。这证明异步结构行为，不证明硬实时或检测性能。
- 33 tick 合成规则回放 0 fault。
- 635 条保存的真实检测/驾驶结果进入最终策略：6 条红灯观测全部停车，旧 v1 为 0/6。普通驾驶 441 条、红灯锁存停车 194 条；194 不是红灯图片数。
- 所有相邻保存帧间隔都超过固定 0.5 s 确认窗口，限速/横道/岔路多帧真实覆盖未执行，没有调宽窗口凑触发。

## 阻塞与安全边界

真正的岔路执行器未注册；旧 left/right.csv 的入口、出口和当前赛道适用性未确认，所以支路意图只能停车保护。真实相机、串口、电机、PL owner、生产异步磁盘日志、检测准确率、15 Hz 和实车均未执行。已经提交的 I/O 不能撤销，写成功不等于 STM32 ACK；软件停车不能替代独立急停。

源码在 `../host/app/ps/control_v2/` 与 `../host/app/tools/control_v2_replay.py`，测试在 `../host/app/tests/`。机器证据见 `../metrics/evidence/control_v2/`。
